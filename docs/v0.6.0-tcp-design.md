# v0.6.0 — TCP checks (implementation slice 1)

## Scope

This branch introduces a standalone TCP checker for one explicitly configured
host and port. It is a building block, not yet wired into the scheduler,
SQLite service registry, history API, or dashboard.

## Configuration contract

A TCP target is represented by:

- `name`: non-empty display name;
- `host`: hostname or IP address, not a URL;
- `port`: integer 1–65535;
- `timeout_seconds`: 0.2–15 seconds.

The checker makes exactly one connection attempt. It does not enumerate ports,
scan ranges, discover hosts, or contact targets not present in configuration.

## Result categories

| Outcome | Status | Category | Severity |
|---|---|---|---|
| TCP handshake succeeds | UP | TCP_CONNECTED | INFO |
| Connection timeout | DOWN | TIMEOUT | ERROR |
| DNS lookup fails | DOWN | DNS_ERROR | ERROR |
| Remote port refuses connection | DOWN | CONNECTION_REFUSED | ERROR |
| Other socket error | DOWN | NETWORK_ERROR | ERROR |

A successful TCP handshake proves only that a connection was accepted at that
moment. It does not prove that the application protocol is healthy.
